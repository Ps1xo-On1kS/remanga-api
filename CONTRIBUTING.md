# Как помочь проекту

Спасибо за желание улучшить справочник.

## Перед отправкой изменений

1. Запустите тесты Kotlin-генератора:

   ```powershell
   cd .\generator
   .\gradlew.bat test --no-daemon
   cd ..
   ```

2. Пересоберите документацию основным генератором или резервным PowerShell-скриптом:

   ```powershell
   .\remanga_api_gen_cli.exe --page-url "https://remanga.org/card" --output "."
   ```

   или:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\generate_api_docs.ps1
   ```

3. Убедитесь, что генератор завершился без ошибок.
4. Не добавляйте пароли, cookies, Bearer-токены и персональные данные.
5. Не вызывайте изменяющие методы ReManga ради проверки документации.

## Что можно улучшать

- русские пояснения к публичным маршрутам чтения;
- проверенные примеры безопасных GET-запросов;
- описание пагинации и фильтров;
- исправления генератора;
- отметки об изменениях между frontend-сборками.

При описании поведения укажите дату проверки и версию frontend из `snapshot-summary.json`.

## Добавление проекта в список

Если ваш проект использует маршруты из этого справочника, добавьте одну запись в раздел «Проекты, использующие API» файла `README.md` и отправьте Pull Request.

В описании PR укажите:

- ссылку на репозиторий или страницу проекта;
- назначение проекта;
- поддерживаемые платформы;
- используемые части API;
- способ установки или запуска.

Проект должен быть доступен для проверки и иметь рабочую версию. Он не должен собирать чужие пароли, cookies или токены, выдавать себя за официальный продукт ReManga или скрывать изменяющие запросы к аккаунту.

Формат записи:

```markdown
- [Название проекта](https://github.com/author/project) - краткое описание и поддерживаемые платформы.
```

Автоматический workflow находится в `.github/workflows/update-api-docs.yml`. Он не вызывает маршруты API: до обнаружения новой сборки выполняется только проверка публичной HTML-страницы.
